쓰기 API는 존재하지 않는다 — 저작은 Activity Builder UI로만. 그래서 브라우저 자동화가 마지막 구간을 맡는다.

A활동·화면 생성activity-plan.md 순서대로. 컴포넌트 이름 정확히 — CL은 이름 의존
B그래프 상태 입력graph-states.md의 LaTeX 줄 목록 붙여넣기 (줄마다 별도 표현식 — 실측 검증) 또는 저장 그래프 URL 임포트
CCL 붙여넣기screen-cl.md → 각 컴포넌트 코드 패널. 패널 오류 표시가 첫 컴파일 검증
D검증 · 발행paste-checklist.md 순회 → 발행 → inspect-amplify.mjs로 공개 JSON 회수해 디프
Claude in Chrome에게 줄 프롬프트 (런북 내장)prompt
classroom.amplify.com에 로그인된 상태야. 다음 활동을 Activity Builder로 만들어줘.
1) 첨부한 activity-plan.md 순서대로 화면과 컴포넌트를 만들고 (이름 정확히),
2) graph-states.md의 표현식을 각 그래프에 순서대로 붙여넣고,
3) screen-cl.md의 CL을 각 컴포넌트 코드 패널에 붙여넣고 오류가 없는지 확인하고,

오류가 나면 멈추고 어떤 컴포넌트의 어떤 줄인지 보고해줘.

검증된 설계 원칙 — 표현식 리스트

전부 1차 자료(공식 문서 번들·뉴스레터·포럼 원문·실측)로 확인. 위키에 출처 링크 보존.

1
그래프가 곧 게임 엔진 VERIFIED
상태·물리·판정·연출은 그래프 표현식이 소유. CL은 number() 주입과 graph.number() 회수만. — "90% of the time, if you can do it in a graph its best to do it that way."
2
timeSincePress는 기본 10초에서 멈춘다 PITFALL
항상 명시 인자 timeSincePress(N). 같은 화면의 다른 컴포넌트에 포커스가 가도 0으로 리셋된다.
3
CL은 변수 자기증가 불가 VERIFIED
점수 누적 표준 3단: 버튼 capture(`C`) → 그래프 numberList(`L`): button.history(`C`) → 표현식 T=total(L)
4
CL에는 산술 연산자가 없다 PITFALL
모든 계산은 numericValue("${x} + ${y}") 경유. 리뷰에서 기존 템플릿의 위반 1건 적발·수정.
5
parseInequality 해집합은 항상 f > 0 VERIFIED
differenceFunction은 (큰쪽)−(작은쪽). 점 판정은 evaluateAt(a,b) 부호 하나. 경계 위(f=0)는 비엄격일 때만 포함시킬 것.
6
real Marbleslides에는 CL이 없다 VERIFIED
sink/source 전무(2018→2026 일관). 점수·잠금이 필요하면 일반 그래프로 클론. real 화면은 Labs 토글로 추가만.
7
키보드 입력 바인딩은 존재하지 않는다 VERIFIED
캐릭터 조작 = 화면 버튼 · 클릭 가능 그래프 오브젝트 · 드래그 포인트 3종뿐.
8
화면 잠금은 가림이지 차단이 아니다 PITFALL
슬라이드 CL coverText: + coverButtonLabel: "" (비공식 싱크). 조건이 틀리면 학생이 영구히 갇힘 — 가드 필수.
9
action 변수와 CL sink 변수는 분리한다 VERIFIED
AB 그래프에서 actions/ticker/clickable 모두 동작하지만, CL sink가 설정하는 변수를 action이 건드리면 sink가 이기거나 무효화 (공식 문서 번들의 정적 분석기 코드로 확인).
10
그래프 상태는 version 11로 생성한다 VERIFIED
수작업 생성 state도 setState() 정상 로드(헤드리스 Chrome 실측). 로더는 v13까지 수용. LaTeX 줄 붙여넣기 = 줄마다 별도 표현식.
11
Challenge Creator는 전면 공개됐다 (2022-10) VERIFIED
학생 출제 메커니즘(Land the Plane형)을 real 컴포넌트로 템플릿화 가능. Function Carnival식 "그리면 애니메이션"도 공식 재구성 레시피 존재.

리뷰가 잡아낸 결함 — 하이라이트

심각도결함 → 수정
CRITICAL 양떼 s04 화면 클리어 불가 — 카운트가 f>0만 세서 경계 위의 양 3마리가 의도된 정답 y ≥ x+1로도 0마리 판정.
→ {f>0.001:1, f>-0.001:1-s, 0} — 비엄격일 때만 경계 포함 + float 등호 대신 ε 비교. 3개 렌즈가 독립적으로 같은 결론.
CRITICAL 존재 불확실한 "Screen CL" 스코프 의존 — 판정 변수를 화면 스크립트에 두고 노트가 bare 참조.
→ 판정 변수를 노트 스크립트 안에 자급자족시켜 comp.script.var 규칙 위반 제거 (table_check·unit_rate_model).
MAJOR CL 산술 연산자 사용 — 기존 randomized_practice가 stairs = 10 * r.int(...) 직접 산술 (CL엔 산술이 없음).
→ 전부 numericValue("...") 경유로 재작성, 허용 오차 경계도 사전 계산.
MAJOR 파싱 실패 시 NaN 노출 — 학생이 y=-0.5x+6처럼 입력하면 "별 NaN / 2개" 표시되고 안내 없음.
→ firstDefinedValue(graph.number(`S`), -1) 가드 + "y= 없이 다시 입력하세요" 전용 분기 (3개 템플릿 모두).
MAJOR dummy 함수 ↔ function() sink 충돌 위험 — 덮어쓰기 보장은 number/numberList만 문서화됨.
→ 그래프 상태에서 dummy g(x)/f(x,y) 제거, 미리보기용 임시 정의는 "CL 연결 전 삭제" 지침으로 대체.
MAJOR 마리오 코인이 제출 전 안 보임 — 코인 표시가 undefined 조건에 묶여 목표 좌표가 안 보이는 빈 무대.
→ 기본 🪙 줄은 무조건 표시, 수집 ✨는 +0.5 오프셋 오버레이로 분리 (라벨 겹침도 해결).
MAJOR 예시 힌트가 정답 유출 — 양떼 s02의 "예: y < 2x+1"이 그 화면의 완전한 정답, 마리오 예시는 레벨1 정답.
→ 리뷰어가 수학적으로 비정답임을 검산한 예시(y > x+4 등)와 꼴 안내로 교체.
